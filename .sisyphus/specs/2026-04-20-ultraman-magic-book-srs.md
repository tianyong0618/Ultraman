## 1. 项目概述

### 1.1 项目背景

Ultraman Magic Book（奥特曼魔法书）是一个面向儿童的互动百科全书Web应用，以古典魔法书的形式呈现1966年至2024年间29个正统奥特曼系列作品。用户可以浏览翻阅魔法书，查看每位奥特曼的详细信息，切换形态，触发技能音效，并聆听语音朗读。

### 1.2 核心用户

| 角色 | 描述 | 优先级 |
|------|------|--------|
| 主要用户 | 4-10岁儿童 | P0 |
| 次要用户 | 家长/成人 | P1 |

### 1.3 产品目标

1. 以视觉吸引力引导儿童了解奥特曼历史
2. 培养阅读兴趣和探索精神
3. 提供沉浸式交互体验
4. 传承奥特曼系列文化

### 1.4 关键约束

- 无需用户登录/注册
- 支持离线缓存阅读
- 响应式布局适配多终端

### 1.5 开发约束（强制）

| 约束 | 描述 |
|------|------|
| 约束1 | 开发过程中必须逐个更新 REQ 状态，禁止批量更新 |
| 约束2 | 归档时必须交叉检查所有待实施提案，确保文档状态与实际代码状态一致 |
| 约束3 | 禁止跳过提案确认步骤直接修改代码 |
| 约束4 | 所有变更必须生成可追溯的文档 |
| 约束5 | 主规范文档必须与代码实现保持一致 |
| 约束6 | 归档时必须同步更新SRS文档的版本历史和模块规范 |

## 2. 功能规范

### 2.1 功能模块

#### 2.1.1 魔法书封面 (BookCover)

**功能描述**: 应用启动时的初始界面，引导用户进入

**界面元素**:
- 魔法书封面图案（皮革纹理+金色边框）
- 标题"奥特曼魔法书"
- 副标题"ULTRAMAN MAGIC BOOK"
- "✦ 开启旅程 ✦" 按钮
- 四个角落装饰符 ✦

**交互规则**:
- 点击按钮后触发翻书动画
- 动画结束后显示书页内容

**验收标准**:
- [x] 封面显示古典魔法书风格
- [x] 金色边框和烫金效果
- [x] 按钮可点击且有悬停效果

#### 2.1.2 翻页系统 (BookPages)

**功能描述**: 核心浏览界面，每页展示一个奥特曼

**页面结构**:
- 左页：图像（无时代标签）
- 右页：名称（格式："名称 · 年份 · 时期"）+ 信息Tabs + 技能按钮
- 底部：翻页按钮 + 页面指示器

**交互规则**:
- 每页固定1个奥特曼（共29页）
- 点击下一页/上一页按钮翻页
- 翻页有3D动画效果（580ms）
- 翻页时重置Tab和形态选择
- 翻页时自动播放当前页名称语音（soundOn=true时）

**验收标准**:
- [x] 翻页动画流畅
- [x] 页面指示器正确显示"当前页 / 总页数"
- [x] 在首页时"上一页"按钮禁用
- [x] 在末页时"下一页"按钮禁用
- [x] 按钮热区 ≥ 44×44px
- [x] 按钮距屏幕边缘 ≥ 16px
- [x] 支持左滑/右滑手势翻页

#### 2.1.3 信息展示 (InfoTabs)

**功能描述**: 右侧页的信息切换展示

**Tab分类**:
| Tab | 内容 |
|-----|-------|
| 形态 | 形态列表（如有）/ "普通形态" |
| 简介 | 剧情简介文本 |
| 人间体 | 人间体名称 / "待补充" |
| 台词 | 经典台词（斜体显示）|

**交互规则**:
- 点击Tab切换显示内容
- 默认激活"形态"Tab（index 0）
- 翻页后自动重置到"形态"Tab

**验收标准**:
- [x] 4个Tab正确显示
- [x] 默认激活形态Tab
- [x] 当前激活Tab有高亮样式

#### 2.1.4 形态切换 (Forms)

**功能描述**: 有多种形态的奥特曼可切换查看

**数据示例**:
```
赛文: ["普通形态", "闪耀版"]
迪迦: ["复合型", "空中型", "强力型", "闪耀型"]
泰罗: ["普通形态", "超级形态", "少年形态"]
```

**交互规则**:
- 只有 forms.length > 0 时才显示形态按钮
- 点击形态按钮切换激活状态
- 翻页后重置到第一个形态

**验收标准**:
- [ ] 无形态显示"无多种形态"
- [ ] 有形态显示所有形态按钮
- [ ] 当前激活形态有高亮样式

#### 2.1.5 技能展示 (Skills)

**功能描述**: 显示并触发技能（含技能动画效果）

**数据示例**:
```
初代: ["斯派修姆光线", "奥特屏障", "奥特水流"]
迪迦: ["哉佩利敖光线", "迪迦拉休尔光流", "兰帕尔特光弹", "迪迦计时器闪光"]
梦比优斯(凤凰形态): ["梦比优斯爆裂", "扎古光线"]
```

**交互规则**:
- 点击技能按钮触发 audio.play()
- 点击技能按钮显示技能图片（动画效果）
- 技能图片路径：`/images/skills/{奥特曼全名}_{技能名}.jpg`
- 技能持续3秒后自动恢复原图
- 空技能显示"暂无技能"
- **【修复 CP-014】** 点击技能时传递技能名而非索引，确保形态特有技能显示正确图片

**验收标准**:
- [x] 技能按钮显示第一个技能名
- [x] soundOn=true 时触发音频
- [x] soundOn=false 时不触发
- [x] 点击技能按钮显示技能图片（淡入效果300ms）
- [x] 技能图片持续3秒后自动恢复原图
- [x] 技能图片加载失败时回退原图
- [x] 形态切换后技能显示对应形态的技能图片（CP-014）

#### 2.1.6 音效开关 (Sound)

**功能描述**: 全局音效/语音开关，同时控制技能音效和语音朗读

**状态**:
- 🔊 开启
- 🔇 关闭

**交互规则**:
- 点击切换状态
- 影响技能音效播放和语音朗读

**验收标准**:
- [x] 点击按钮切换图标
- [x] 状态翻页后保持

#### 2.1.7 语音朗读 (Voice)

**功能描述**: 语音朗读增强儿童交互体验

**触发场景**:
| 触发条件 | 朗读内容 | 音频来源 |
|---------|---------|---------|
| 翻页进入 | 奥特曼名称 | name/{name}.mp3 |

**技术方案**:
- 音频生成工具: edge-tts (免费CLI)
- 语音库: zh-CN-XiaoxiaoNeural
- 存储位置: public/audio/

**交互规则**:
- 声音默认开启 (soundOn = true)
- 翻页时自动播放当前页名称音频
- 快速连续操作时取消前一个音频

**验收标准**:
- [x] soundOn=true 时翻页自动播放名称
- [x] soundOn=false 时不播放

#### 2.1.8 全家福 (FamilyPortrait)

**功能描述**: 全屏展示全部29个奥特曼头像及关系连线

**界面元素**:
- 全屏星空背景（闪烁动画）
- 29个随机分布的奥特曼头像（热门在中间）
- 相关奥特曼之间的光束连线
- 筛选模式下无关头像置灰
- 响应式布局（桌面/移动端适配）

**交互规则**:
- 点击"开启旅程"后显示全家福页面
- 点击头像跳转到对应书页
- 点击书页的"关系"Tab进入筛选模式
- 筛选模式下相关头像正常显示，选中头像高亮
- 悬浮时放大效果（桌面/移动端）
- 位置缓存（区分桌面/移动端）

**验收标准**:
- [x] 全屏星空背景显示
- [x] 29个头像随机分布（位置缓存刷新不变）
- [x] 热门英雄（关系≥2）在中心30%区域
- [x] 关系连线显示
- [x] 点击头像跳转书页
- [x] 筛选模式无关头像置灰
- [x] 选中头像高亮
- [x] 移动端适配（统一36px头像，不重叠）
- [x] 移动端悬浮放大效果

**技术实现**:
- `sessionStorage` 缓存位置，key: `ultraman_positions_desktop` / `ultraman_positions_mobile`
- `calculatePopularity()` 计算关系数量
- `generatePositionsByPopularity()` 按活跃度生成位置
- 移动端边距30px，间距50px，头像36px

### 2.2 数据结构

## 6. 需求变更流程

### 6.1 变更类型

| 类型 | 说明 | 影响范围 |
|------|------|----------|
| BUG修复 | 缺陷修复 | 回归测试 |
| 优化 | 性能/体验提升 | 局部测试 |
| 新功能 | 功能扩展 | 全面测试 |
| 重构 | 架构调整 | 全面测试 |

### 6.2 变更流程

```
提案 → 开发 → 验证 → 合并 → 归档
  ↓     ↓     ↓      ↓
 规格   代码   测试  主分支  版本记录
文档   实现   通过  自动
```

#### 6.2.1 提案阶段

1. 创建Issue描述需求
2. 讨论实现方案
3. 确认优先级

#### 6.2.2 开发阶段

1. 创建功能分支
2. 实现代码
3. 添加测试用例
4. **【新增】每个 REQ 完成后立即更新文档状态**

#### 6.2.3 验证阶段

1. 本地测试通过
2. 代码审查通过
3. 合并到主分支

#### 6.2.4 归档阶段

1. 更新规格文档
2. 更新版本号
3. 关闭Issue
4. **【新增】交叉检查所有待实施提案状态**
5. **【强制】同步更新SRS文档**
   - 更新SRS版本号和日期
   - 在对应模块规范中反映变更内容
   - 在版本历史中添加变更记录
   - 确保数据清单（29个奥特曼）与实际数据一致
   - 确保数据结构与实际代码一致（forms为对象数组）
   - 确保infoLabels与实际代码一致（4个Tab）

#### 6.2.5 SRS文档同步规范（强制）

归档时必须同步更新SRS文档的以下内容：
